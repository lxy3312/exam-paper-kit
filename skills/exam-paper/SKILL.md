# 出卷子

本 skill 自带排版引擎（`kit/`，基于 ReportLab + PyMuPDF）、脚本（`scripts/`）和模板（`templates/`）。
下文的 `<skill>` 指 SKILL.md 所在目录（装在哪个工具的 skills 目录里都一样）。如果项目里有给这个学生的笔记（学情、错题档案、以前的卷子），**先读笔记**再动手。

## 一、开工前定下来（能从笔记和原卷推出来的就别问）

1. **范围**：哪本教材、哪几章。按学校进度和考试时间推。例：人教版九上期中＝第 21～24 章（一元二次方程、二次函数、旋转、圆），
   全册再加第 25 章概率。拿不准就看同一时段的名校原卷考到哪儿。
2. **结构**：北京期中/中考数学卷是单选 8×2、填空 8×2、解答 12 道 68 分（第 17～25 题 5 或 6 分，26 题 6 分，27、28 题 7 分），
   满分 100、120 分钟。大卷（比如 300 分）就分几次做，每次 100 分。
3. **难度**：「超难」＝每个题位都挑最难的那道（见 `reference/题源.md` 的「哪个题位最难」）。
4. **交付形式**：试卷、答案两个文件（`X.pdf` ＋ `X（答案）.pdf`），需要的话加水印。

## 二、选题（最耗时的一步，照下面做能省一大半）

1. `python <skill>/scripts/used_sources.py --dir 出卷脚本目录 [关键词]`：列出以前的卷子用过哪些原题，**不重复**。
2. **按题位直接裁**，别整份整份翻：先 `crop.py 原卷.pdf 页 0 0 1 1 小图.png 80` 看题在哪儿，
   再 190～220dpi 裁那一道（`crop.py 原卷.pdf 页 x0 y0 x1 y1 题.png`），直接看图抄题。扫描件也能看图，别说「提取不到」。
3. 原题**题干照抄、标出处**（学校＋学年＋第几题）；原创的写「原创」，不冒充真题。为了躲开行首标点改一两个字可以，交付时说明。
4. 公开考试卷的使用要遵守当地规定和来源网站的条款；仓库里不要放原卷文件。

## 三、写脚本（从模板起步，别从头写）

把 `<skill>/templates/` 里三个模板复制到出卷目录，改名、改掉 `xxx` 模块名。模板会自己找 `<skill>/kit`（环境变量 `EXAM_PAPER_KIT` → 当前目录往上的各家 skills 目录 → 用户目录），找不到就把模板里的 `KIT` 改成实际路径：

| 模板 | 复制成 | 作用 |
|---|---|---|
| `build_template.py` | `build_<名字>.py` | 题目、答案、卷面结构，出两个 PDF |
| `figs_template.py` | `<名字>_figs.py` | 配图，`*_points()`＋`audit()` |
| `verify_template.py` | `verify_<名字>.py` | 答案验算 |

- 题目按 id 存：`("四中16", lambda s, c: fill(s, "14.（北京四中2024—2025学年初三上期中第16题）……", c, F.fig_q12))`。
  卷面题号、图注里的「第N题」、答案页题号、`P.nums()` 写的答案来源都按位置自动给——**调顺序只挪列表条目**，题干开头的数字只是占位。
- 题型（`kit/paper_kit.py`）：`cq` 选择（结论用 `\n` 分行，`per_row` 控制一行几个选项）、`fill` 填空（横线写「＿＿＿＿」）、
  `qb` 大题（`figs` 和题干绑一块，`spare` 备用图可单独流到下一栏，`groups` 把长题按小问切块，`tab` 夹表格，`after` 接一个 Note）。
- 答案放 `ANSWER[id]`；选择题答案以字母开头（`P.key()` 取首字母拼答案串）。每道写清来源：官方答案／解析版／自己解的。
- 写完先 `python <skill>/scripts/lint_markup.py build_<名字>.py`：√、÷ 吞括号、缺字形这些坑让它先拦（细节见 `reference/坑.md`）。

## 四、画图

规矩写在 `templates/figs_template.py` 开头：点由题干条件算、`*_points()` 和图共用一组点、练习题的图不画答案点、
几何大题三张图（图1、图2、备用图）、`audit()` 逐条核（等长、垂直、共线、在圆上、旋转方向……）。
画完用 `python <skill>/kit/contact_sheet.py <名字>_figs 总览.png fig_` 拼一张图看一遍（在出卷目录里跑，kit 要在 sys.path 上）。

## 五、验算

每个数值答案都用程序算一遍，取值范围一律扫描、端点单独判断，几何结论多换几组参数（模板里有写法）。
`verify_<名字>.py` 打印「全部通过」才往下走；选择题答案串要和答案页一致（模板最后一段会比）。

## 六、排版

1. 第一次出 PDF 之前先模拟：`python <skill>/scripts/packsim.py build_<名字>.py [--keep-section 4] [--fix id,id]`。
   它在每个关卡内部、同分值的题之间换顺序，找栏数最少、栏底最大空白最小的排法，最后打印一条 `reorder.py` 命令，照着跑。
2. 出 PDF 到临时目录（`build(path, ans_path)` 可以传路径），量：
   `python <skill>/scripts/check_pdf.py 卷.pdf --watermark 水印字 --png 目录 --montage 目录`，**然后真的看图**
   （总览图看整体，单页放大看公式、断行、图）。
3. 空白：作答区留白是正常的；题目区栏底空 > 60mm 的，先调顺序，再考虑补备用图、挂一个 Note，最后才缩图。
   题干和选项、题干和要看的图绝不拆开——宁愿留空也不拆。
4. 行首标点：`check_pdf.py` 报出来就改措辞（多一个字、少一个字就能挪开），别加空格硬顶。

## 七、交付

1. 正式版再跑一遍：`verify_<名字>.py` 全过、`check_pdf.py`（行首标点无、水印每页都有）、真看一遍渲染图。
2. 把两个 PDF 交给用户，说清楚：范围、结构、题源、答案怎么核的、选择题答案串、页数。用用户的语言，说人话。
3. 有项目笔记就补一节：原话、范围依据、题源和答案来源、自己解出来值得记的结论、踩到的新坑。

## 为什么要这么走

第一次照「先写完再排」的做法出一份 100 分卷，时间大半耗在三处：整份翻扫描卷选题；题号写死在题干里，排完发现空白多，
回头改结构再调顺序；一串可以提前拦住的小错（公式写法、字形）。按题位取题、从模板起步、先 lint 和 packsim 再出 PDF，
同样一份卷子能快一半以上。验算和配图审计不要省：错图比错答案更坑。
